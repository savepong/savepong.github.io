บอกไว้ก่อนเลยครับว่าโน้ตต้นทางของเรื่องนี้ในคลังความรู้ผมยังเป็น stub อยู่ คือจดไว้กันลืม ยังไม่ได้ลงลึก เพราะงั้นบทความนี้จะสั้นหน่อย ผมจะเล่าแค่เท่าที่มีจริง ไม่เติมสีให้ดูเยอะครับ

## ปัญหาที่ Proxmox มาแก้

เวลาเราอยากมีเครื่องหลาย ๆ เครื่องไว้ลองของ — ตัวนี้รัน database ตัวนั้นรัน web ตัวนี้เอาไว้พังเล่น — ทางเลือกแรกที่คนส่วนใหญ่นึกถึงคือไปเช่า cloud แต่พอของเริ่มเยอะ บิลก็เริ่มน่ากลัว

Proxmox VE คือแพลตฟอร์ม virtualization แบบโอเพนซอร์ส ที่ให้เราเอาเครื่องจริงหนึ่งเครื่องมาซอยเป็นเครื่องย่อย ๆ หลายตัวได้ แล้วจัดการทุกอย่างผ่านหน้าเว็บเดียว

เปรียบง่าย ๆ ครับ ถ้า cloud เหมือนเช่าคอนโดรายเดือน Proxmox ก็เหมือนซื้อบ้านหนึ่งหลังแล้วกั้นห้องเองตามใจ ลงทุนก้อนแรกแล้วหลังจากนั้นกั้นห้องเพิ่มกี่ห้องก็ไม่มีใครมาเก็บเงินเพิ่ม แต่ท่อรั่วหลังคาพังก็ซ่อมเองนะครับ อันนี้คือราคาที่ต้องจ่าย

## จุดที่น่าสนใจ: มันให้มาสองแบบ

สิ่งที่ผมว่าเป็นแก่นของ Proxmox จริง ๆ คือมันรวมเทคโนโลยีสองตัวไว้ในที่เดียว คือ **KVM** กับ **LXC**

KVM คือ virtual machine เต็มรูปแบบ — จำลองเครื่องขึ้นมาใหม่ทั้งตัว มี kernel ของตัวเอง อยากลง Windows อยากลง Linux คนละ distro ก็ได้หมด แลกมากับความหนัก

LXC คือ container — ไม่ได้จำลองเครื่องใหม่ แต่ขอ "กั้นพื้นที่" บน kernel ของเครื่องแม่ เบากว่า เปิดเร็วกว่ามาก แต่ก็ผูกกับเครื่องแม่มากกว่าด้วย

กลับไปที่บ้านหลังเดิมครับ KVM เหมือนสร้างบ้านอีกหลังในที่ดินเดียวกัน มีมิเตอร์น้ำมิเตอร์ไฟของตัวเอง ส่วน LXC เหมือนกั้นห้องในบ้านหลังเดิม ใช้ท่อน้ำท่อไฟร่วมกัน

ซึ่งมันแปลว่าเราเลือกตามงานได้ งานที่ต้องการ OS แปลก ๆ หรือต้องแยกขาดจริงจัง ก็ไป KVM งานเล็ก ๆ ที่แค่อยากให้มันอยู่คนละกล่อง เช่นเซอร์วิสเล็ก ๆ ที่รันตลอด ก็ LXC ไป ประหยัดทรัพยากรไปเยอะ

พอยท์ที่คนมักพลาดคือ ไปใช้ KVM กับทุกอย่างเพราะมันคุ้นมือกว่า แล้วก็มางงว่าทำไมเครื่องเต็มเร็ว

## ที่ผมสนใจคือจับคู่กับ Terraform

ในโน้ตผมมีอีกประเด็นที่โยงกันอยู่ คือเรื่องการทำ **IaC** หรือ Infrastructure as Code ด้วย Terraform

ไอเดียของ IaC คือเลิกคลิกสร้างเครื่องด้วยมือ แล้วเขียนลงไฟล์แทนว่าเราอยากได้เครื่องหน้าตาแบบไหน กี่ตัว แล้วสั่งให้เครื่องมือไปสร้างให้ ข้อดีคือ config ของเราอยู่ใน git ย้อนดูได้ว่าใครแก้อะไร และสร้างใหม่ให้เหมือนเดิมได้ทุกครั้ง

แล้ว Proxmox + Terraform ก็เป็นทางเลือก self-hosted ที่ใช้งานได้จริงแทน AWS หรือ GCP สำหรับงานที่กดต้นทุนเป็นหลักครับ เราได้วินัยแบบ cloud คือทุกอย่างเป็นโค้ด แต่ไม่ได้บิลรายเดือนแบบ cloud มาด้วย

## สรุปแบบไม่อวย

ตรงนี้ผมต้องซื่อสัตย์ครับ ผมยังไม่ได้ใช้ Proxmox หนักพอจะบอกว่ามันพังตรงไหน เจ็บตรงไหน บทความนี้เลยเป็น "ทำไมมันน่าสนใจ" ไม่ใช่ "ใช้แล้วเป็นอย่างไร" ตัวเลข performance หรือเคสเจ๊งกลางทาง ผมไม่มีให้ และไม่อยากเดาให้ฟังครับ

ถ้าวันไหนได้ลงมือจริงจัง ผมจะกลับมาเขียนรอบสองแบบมีแผลให้ดูครับ
