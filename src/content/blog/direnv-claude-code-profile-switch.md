เคยเจอไหมครับ นั่งทำงานลูกค้าอยู่ แล้วเผลอยิง Claude Code ด้วย account ส่วนตัว ประวัติแชทงานลูกค้าไปกองรวมกับของที่บ้าน MCP ที่ต่อไว้ก็ปนกันหมด

ปัญหาคือมันไม่ได้เกิดจากความขี้เกียจ มันเกิดจากเราต้อง "จำ" ว่าตอนนี้อยู่โฟลเดอร์ไหนแล้วต้องใช้โปรไฟล์อะไร อะไรที่ต้องอาศัยความจำมนุษย์ มันพลาดวันยังค่ำครับ

วิธีที่ผมจะเล่าวันนี้คือย้ายภาระนั้นออกจากหัวเรา ไปให้ shell จัดการแทน แค่ `cd` เข้าไป โปรไฟล์ก็สลับให้เอง

## ชิ้นที่หนึ่ง: direnv

direnv เป็น shell extension ที่ทำหน้าที่เดียว คือโหลดและเลิกโหลด environment variable ตาม directory ที่เราอยู่

กลไกมันเรียบง่ายมาก ก่อนจะวาด prompt ให้เราทุกครั้ง มันจะไปเช็กว่ามีไฟล์ `.envrc` อยู่ใน directory ปัจจุบันหรือ parent directory ไหม ถ้ามีก็โหลดตัวแปรในนั้นให้ แล้วพอเรา `cd` ออกไปที่อื่น มัน unset คืนให้อัตโนมัติ

สองเรื่องที่ต้องรู้ก่อนใช้ครับ

เรื่องแรก ต้อง hook มันเข้า shell ก่อน zsh ก็ใส่บรรทัดนี้ท้าย `~/.zshrc`

```bash
eval "$(direnv hook zsh)"
```

bash กับ fish มี syntax ของตัวเอง ใส่แล้ว restart shell ด้วย

เรื่องที่สอง ไฟล์ `.envrc` ใหม่มันจะไม่โหลดให้เองนะครับ ต้องสั่ง

```bash
direnv allow .
```

อันนี้เป็นกลไกความปลอดภัย ลองคิดภาพว่าเรา clone repo มาจากอินเทอร์เน็ต แล้วในนั้นมี `.envrc` ที่สั่งลบดิสก์ทิ้ง ถ้า direnv โหลดเองทันทีก็จบเลยครับ เลยต้องให้เจ้าของเครื่องกดอนุญาตทีละไฟล์

คำสั่งอื่นที่ใช้บ่อย `direnv edit .` เปิดไฟล์ให้แก้แล้ว allow ให้อัตโนมัติถ้า mtime เปลี่ยน, `direnv status` ดูสถานะ, และ `watch_file <file>` สำหรับสั่งให้ reload เมื่อไฟล์นั้นเปลี่ยน

## ชิ้นที่สอง: CLAUDE_CONFIG_DIR

ปกติ Claude Code เก็บของทุกอย่างไว้ที่ `~/.claude` ทั้ง settings, history, MCP auth, plugin state

แต่มันอ่าน path นี้มาจาก environment variable ชื่อ `CLAUDE_CONFIG_DIR` ครับ ซึ่งแปลว่าถ้าเรา set ตัวแปรนี้ไปที่ path อื่น มันจะย้ายไปใช้ที่นั่นทั้งก้อน

ขอเน้นคำว่า "ทั้งก้อน" นะครับ เพราะนี่คือจุดที่มันน่าสนใจ เราไม่ได้แยกแค่ไฟล์ setting แต่ได้ profile ที่แยกกันสนิท คนละ login คนละ MCP คนละ history

## เอาสองชิ้นมาต่อกัน

ถึงตรงนี้คำตอบมันค่อนข้างชัดแล้วใช่ไหมครับ ถ้า direnv set ตัวแปรตามโฟลเดอร์ได้ และ Claude Code เปลี่ยน profile ตามตัวแปรได้ เราก็แค่เอามันมาเจอกัน

```bash
# ~/work/.envrc
export CLAUDE_CONFIG_DIR=$HOME/.claude-work
```

แล้ว

```bash
cd ~/work && direnv allow .
```

เสร็จครับ

ประเด็นสำคัญที่ผมอยากให้สังเกตคือ ผมวาง `.envrc` ไว้ที่ `~/work` ซึ่งเป็น parent folder ไม่ใช่วางในทุก repo ย่อย เพราะ direnv ไล่หาไฟล์จาก parent ด้วย เลยหมายความว่า repo ไหนก็ตามที่อยู่ใต้ `~/work` ไม่ว่าจะเป็น `~/work/project-a` หรือ `~/work/clients/acme` มันได้ `CLAUDE_CONFIG_DIR` ตัวนี้ไปโดยอัตโนมัติหมด พอ cd ออกไปที่อื่นก็ unset กลับ

## แบ่ง profile ตาม trust boundary ไม่ใช่ตาม repo

อันนี้เป็นความเห็นผมล้วน ๆ นะครับ แต่ผมว่ามันคือหัวใจของการใช้วิธีนี้ให้รอด

เส้นแบ่งที่ควรใช้คือ "trust boundary" เช่น personal / work / ลูกค้าแต่ละราย ไม่ใช่แบ่งทีละ repo ไม่งั้นเดี๋ยวจะมี profile เยอะเกินความจำเป็น แล้วกลับไปสู่ปัญหาเดิมคือดูแลไม่ไหว

layout ที่ผมแนะนำหน้าตาประมาณนี้

```
~/.claude-profiles/personal/
~/.claude-profiles/work/company/
~/.claude-profiles/clients/acme/
```

แต่ละโฟลเดอร์ย่อยมี `.envrc` ของตัวเอง export `CLAUDE_CONFIG_DIR` ไปที่โฟลเดอร์ profile ที่ตรงกัน

## ขั้นกว่า: สลับ account ไปด้วยเลย

อันนี้เป็นของเสริม ไม่ใช่ core นะครับ

บางคนเขา set `CLAUDE_CODE_OAUTH_TOKEN` คู่ไปกับ `CLAUDE_CONFIG_DIR` ใน `.envrc` เดียวกัน โดยอ่าน token จากไฟล์ที่เก็บไว้ใน profile dir นั้น

ผลคือมันไม่ใช่แค่สลับ settings แต่สลับ account จริง ๆ ไปด้วยพร้อมกัน

## ขี้เกียจเขียนมือ ก็มีของสำเร็จ

ถ้าไม่อยากนั่งเขียน `.envrc` เอง มีเครื่องมือที่เขียนให้อัตโนมัติอยู่สองตัวครับ

`agentprofiles-cli` รองรับทั้ง Claude Code และ OpenCode

`claude-code-profile` หรือ `ccp` รองรับทั้ง mise และ direnv

## หลุมพรางที่อยากเตือนไว้ก่อน

ข้อแรกเจ็บที่สุด ถ้าไม่ได้ hook shell ไว้ก่อน `.envrc` จะไม่ทำงานเลยแบบเงียบ ๆ ไม่มี error ไม่มีคำเตือนอะไรทั้งนั้น นั่งงงอยู่เป็นชั่วโมงได้เลยครับ

ข้อสอง ไฟล์ `.envrc` ที่แก้ไขแล้วต้อง `direnv allow` ใหม่ ไม่งั้นมันจะใช้ของเก่าค้างอยู่ อันนี้เป็นผลพลอยเสียจากกลไกความปลอดภัยที่เล่าไปตอนต้น

ข้อสาม อย่าหลงใส่ `.envrc` ทุก repo ย่อย เดี๋ยวดูแลไม่ไหว วางที่ parent folder ของกลุ่มงานพอครับ

## สรุป

วิธีนี้ไม่มีอะไรหรูหราเลยครับ แค่ตัวแปรหนึ่งตัวกับไฟล์หนึ่งไฟล์ แต่สิ่งที่ได้คือเลิกต้องจำว่าตอนนี้ตัวเองอยู่โปรไฟล์ไหน

และสำหรับงานที่มีเส้นแบ่งเรื่องข้อมูลลูกค้าอยู่ ของที่ "ไม่ต้องจำ" มันปลอดภัยกว่าของที่ "ต้องจำแล้วห้ามพลาด" เยอะครับ
