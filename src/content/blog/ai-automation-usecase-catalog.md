เวลาเราเริ่มเล่นกับ AI agent ปัญหาแรกมันไม่ใช่ "ทำได้ไหม" ครับ มันคือ "แล้วจะเอาไปทำอะไรดี"

ผมเจออาการนี้กับตัวเองเลย มีเครื่องมือครบมือ มี agent วิ่งได้ มี cron ตั้งได้ แต่พอถามตัวเองว่า "ต่อไปจะ automate อะไร" ก็ตอบไม่ได้ สุดท้ายก็วนไปทำอันที่เพิ่งคิดออกตอนนั้น ซึ่งมักจะเป็นอันที่ง่าย ไม่ใช่อันที่คุ้ม

วิธีแก้ของผมคือนั่งเขียนทุกอย่างที่อยากให้ระบบทำออกมาเป็นลิสต์เดียว ได้มา 37 ข้อ แล้วแบ่งเป็น 5 หมวด คือ งานส่วนตัว งานบริษัท ตัวโปรดักต์เอง งานคอนเทนต์/คอมมูนิตี้ และหมวดสุดท้ายที่ผมชอบที่สุด — งานที่ระบบปรับปรุงตัวมันเอง

## ทำไมต้องเป็นลิสต์เดียว

คิดภาพเมนูร้านอาหารครับ

ถ้าเชฟทำได้ 37 อย่างแต่ไม่เคยเขียนเมนู ลูกค้าก็สั่งได้แค่ของที่นึกออก แล้วเชฟก็จะทำซ้ำ ๆ อยู่ 5 อย่างเดิมไปตลอด เมนูไม่ได้เพิ่มความสามารถให้เชฟเลย แต่มันทำให้ความสามารถที่มีอยู่แล้ว *ถูกเรียกใช้*

ลิสต์ของผมก็หน้าที่เดียวกัน เวลาผมถามตัวเองว่าจะทำอะไรต่อ ผมไม่ได้เริ่มจากศูนย์ ผมเปิดลิสต์

## ติ๊กดาวไว้ด้วย

สิ่งที่ผมทำเพิ่มคือใส่ดาวหน้าข้อที่ "สร้างแล้วและทดสอบแล้วว่าใช้ได้จริง"

ฟังดูเป็นรายละเอียดเล็ก ๆ แต่มันสำคัญมากครับ เพราะตอนเขียนลิสต์มันง่ายมากที่จะเผลอเขียนของที่ "ออกแบบไว้แล้ว" ปนกับของที่ "ทำงานอยู่จริง" แล้วพอผ่านไปสองเดือนเราจะจำไม่ได้ว่าอันไหนเป็นอันไหน

ของผมติ๊กดาวได้ไม่กี่ข้อจาก 37 ครับ — อย่างสรุปข่าวตอนเช้าส่งเข้าแชต สรุปงาน dev ประจำวัน รายงานสถานะโปรเจกต์ทุกเย็นศุกร์ แค่นี้ ส่วนที่เหลือคือ "คิดไว้แล้ว ยังไม่ได้ทำ" ซึ่งการเห็นสัดส่วนนี้ตรง ๆ ก็ทำให้ผมเลิกหลอกตัวเองว่าระบบเสร็จแล้ว

## บทเรียนที่แพงที่สุดอยู่ท้ายลิสต์

ตอนท้ายผมจดบทเรียนเชิงปฏิบัติไว้ด้วย ซึ่งเอาจริง ๆ ส่วนนี้มีค่ากว่าตัว use-case เยอะ

อันที่ผมเจ็บที่สุดคือเรื่องการเลือกโมเดลให้ agent ที่วิ่งอัตโนมัติ ผมเคยเจอว่าโมเดลตัวหนึ่งมันตอบแล้ว "เดินเรื่อง" ออกไปเรื่อย ๆ จนข้อความยาวเกินลิมิตของ provider แล้วพังด้วย error ว่ายาวเกิน ไล่หาสาเหตุอยู่นาน สุดท้ายคือต้องไปแก้ที่ตัวเลือกโมเดล ไม่ใช่ที่ prompt

อีกเรื่องคือ provider ตัวนั้นจำกัดจำนวนข้อความต่อหนึ่ง request ด้วย แปลว่า agent ที่วิ่งเองตามเวลาต้องถูกตัดเครื่องมือที่ไม่จำเป็นออก (ผมตัด search ออกเลย) แล้วเขียน prompt ให้ขอบเขตแคบ ๆ ชัด ๆ ไม่ใช่ปล่อยให้มันไปสำรวจเอง

เห็นแพตเทิร์นไหมครับ ของที่พังไม่ใช่ตรรกะของงาน แต่เป็นงบประมาณ — จำนวนข้อความ ความยาว ขอบเขตของเครื่องมือ **agent ที่ทำงานตอนเราไม่อยู่ ต้องถูกใส่กรอบมากกว่า agent ที่เราคุยด้วยสด ๆ** เพราะไม่มีใครดึงมันกลับเข้าทางกลางคัน

## สิ่งที่ผมจะทำถ้าย้อนเวลาได้

เขียนแคตตาล็อกก่อน แล้วค่อยสร้าง

ไม่ใช่เพราะมันทำให้สร้างเร็วขึ้น แต่เพราะเวลาเรามีลิสต์อยู่ตรงหน้า เราจะเลือกข้อที่ *คุ้ม* ไม่ใช่ข้อที่ *นึกออก* ซึ่งสองอันนี้ไม่ค่อยตรงกันเลยครับ
