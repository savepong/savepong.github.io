คืองี้ครับ สมมติคุณลง Ollama ไว้ในเครื่องเรียบร้อย โมเดลรันได้ ตอบได้ ทุกอย่างสวยงาม แล้วคุณก็คิดต่อว่า "งั้นเอา AI ใน Warp Terminal มาใช้โมเดลตัวนี้เลยสิ ฟรี แล้วก็ไม่ต้องส่งข้อมูลออกนอกเครื่อง"

ฟังดูเข้าท่ามากครับ แต่ทำไม่ได้ และที่น่าสนใจคือ *เหตุผล* ที่ทำไม่ได้

## ปัญหาไม่ได้อยู่ที่การตั้งค่า

Warp มีฟีเจอร์ BYOK (Bring Your Own Key) และ custom inference endpoint จริง อันนี้ผมเช็คมาแล้วว่ามีจริงไม่ใช่แค่เขียนไว้ในเอกสาร — ไล่ดู string ในตัวแอปก็เจอ schema ที่รองรับ custom model provider อยู่จริง ๆ มี field สำหรับ config กับ API key พร้อม (ส่วนเรื่องแพลน: ใช้ได้ทั้ง Free และแบบจ่ายเงิน ถ้าองค์กรไม่เกิน 10 คน ใหญ่กว่านั้นต้อง Business/Enterprise)

แต่เอกสารของ Warp เขียนไว้ตรง ๆ ว่า endpoint ที่คุณใส่ **ต้องเข้าถึงได้จากอินเทอร์เน็ตสาธารณะ** และ `localhost` กับ address ในเน็ตเวิร์กภายในจะถูกปฏิเสธ

เหตุผลอยู่ที่ว่า AI agent ของ Warp ไม่ได้รันอยู่ในเครื่องคุณครับ มันรันอยู่บนเซิร์ฟเวอร์ของ Warp แล้ว *เซิร์ฟเวอร์ของ Warp* เป็นคนยิง request ไปหา endpoint ที่คุณตั้งไว้ — คำขอไม่ได้ออกจากเครื่องคุณเลย

ลองคิดเป็นภาพนี้ครับ: คุณสั่งอาหารผ่านแอป แล้วบอกว่า "ไปเอาวัตถุดิบในตู้เย็นผมมาทำนะ" ครัวเขาอยู่อีกที่หนึ่ง เขาเปิดตู้เย็นในบ้านคุณไม่ได้ ไม่ใช่ว่าเขาขี้เกียจ แต่เขายืนอยู่คนละที่กับตู้เย็นของคุณ

`localhost` ของ Warp server ไม่ใช่ `localhost` ของเรา มันเลยไม่ใช่บั๊ก ไม่ใช่เมนูที่ซ่อนอยู่ มันคือข้อจำกัดเชิงสถาปัตยกรรม

## แล้วเปิด tunnel ออกไปเลยล่ะ?

ทางเทคนิคได้ครับ ngrok, Tailscale Funnel, Cloudflare Tunnel — ทำให้ Ollama ในเครื่องมี public URL ได้จริง แต่ผมบอกเลยว่าอย่าทำ ด้วยสามเหตุผล

หนึ่ง Ollama ไม่มีระบบ auth มาให้ในตัว การเปิด tunnel สาธารณะคือการแปะ inference endpoint เปล่า ๆ ไว้กลางอินเทอร์เน็ต ใครเจอก็ยิงได้

สอง เส้นทางของข้อมูลจะกลายเป็น เครื่องคุณ → เซิร์ฟเวอร์ Warp → tunnel สาธารณะ → กลับมาที่เครื่องคุณ ช้ากว่าและเป็นส่วนตัวน้อยกว่าการใช้ cloud provider ตรง ๆ เสียด้วยซ้ำ

สาม — อันนี้คือหมัดน็อก — มันทำลายเหตุผลทั้งหมดที่เราอยากรันโมเดลในเครื่องตั้งแต่แรก คือความเป็นส่วนตัว ใช้ออฟไลน์ได้ และข้อมูลไม่ออกจากเครื่อง อ้อมโลกไปขนาดนั้นแล้วได้อะไรกลับมาครับ

## สรุปว่าควรจัดของยังไง

ผมเลยแยกหน้าที่กันแบบนี้

**AI ใน Warp** ใช้ Anthropic ตรงแบบ BYOK (ผมเลือก `claude-sonnet-5`) ที่ไม่ผ่าน proxy อย่าง OpenRouter เพราะ Warp ส่ง system prompt ซ้ำใหม่ทุกเทิร์น การต่อ Anthropic ตรงทำให้ใช้ prompt caching ของเขาได้ ซึ่งตัดค่าใช้จ่ายส่วนที่ซ้ำ ๆ นั้นลงได้ราว 10 เท่า — ของแบบนี้ proxy ส่วนใหญ่ไม่มีให้ แถมได้ dashboard ดูยอดใช้จริงด้วย

**Ollama** เก็บไว้ทำงานที่ต้องการความเป็นส่วนตัวหรือออฟไลน์จริง ๆ รันตรงในเทอร์มินัลก็ได้ หรือใช้ผ่าน endpoint แบบ OpenAI-compatible ของมัน (ผมยืนยันแล้วว่าทั้ง chat completions และ tool-calling ใช้ได้) กับเครื่องมือที่ยอมรับ local base URL เช่น Zed, Continue.dev, Open WebUI, Raycast AI

หลักการจำง่าย ๆ ครับ: **เครื่องมือที่วิ่งผ่านเซิร์ฟเวอร์ของเจ้าของแอปก่อน จะต่อโมเดลในเครื่องเราไม่ได้** ไม่ว่าเอกสารจะบอกว่ารองรับ custom endpoint แค่ไหนก็ตาม เวลาจะเลือกเครื่องมือ ลองถามคำถามเดียวนี้ก่อน — "ใครเป็นคนยิง request" ถ้าคำตอบไม่ใช่เครื่องเรา เรื่อง local model ก็จบตรงนั้นครับ
