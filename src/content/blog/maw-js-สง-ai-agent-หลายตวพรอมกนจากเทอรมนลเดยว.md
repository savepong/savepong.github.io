คืองี้ครับ เวลาเราใช้ AI agent ทำงานจริงจัง ปัญหามันไม่ได้อยู่ที่ agent ตัวเดียวเก่งหรือไม่เก่ง แต่มันอยู่ที่ว่า "พอมีหลายตัวแล้วเราจะคุมมันยังไง" เปิดเทอร์มินัลห้าหน้าต่าง สลับไปสลับมา สุดท้ายลืมว่าตัวไหนทำอะไรค้างไว้

maw-js คือเครื่องมือที่เกิดมาแก้ปัญหานี้ครับ ชื่อเต็มคือ **Multi-Agent Workflow CLI** ไอเดียมันเรียบง่ายมาก คือเอา tmux (ตัวจัดการหน้าต่างในเทอร์มินัล) มาเป็นบ้านให้ agent อยู่ แล้วเขียน CLI ด้วย Bun ครอบไว้ข้างบน จบด้วยสามคำสั่งหลัก: `maw wake` ปลุก agent ขึ้นมา, `maw hey` ส่งงานให้มัน, `maw ui` เปิดแดชบอร์ดดูทุกตัวพร้อมกัน

ลองคิดภาพเหมือนออฟฟิศนะครับ tmux คือตัวตึกที่มีห้องให้พนักงานนั่ง maw คือหัวหน้าที่เดินไปเคาะประตูสั่งงานทีละห้อง แล้วแดชบอร์ดก็คือกล้องวงจรปิดที่ให้เราเห็นทุกห้องในจอเดียว

## สถาปัตยกรรมที่น่าสนใจ

ของที่ผมว่าออกแบบดีคือเขาแยกเป็น **Entry → Dispatch → Transport** ชัดเจน

ชั้น transport ตอนนี้ไม่ผูกกับ tmux อย่างเดียวแล้วครับ มันมี `TransportRouter` ที่จัดลำดับความสำคัญแล้ว fallback ไล่ไปเรื่อย ๆ ตั้งแต่ tmux, HTTP, Scout (P2P), Zenoh ไปจนถึง NanoClaw แปลว่าถ้าทางหนึ่งล่ม มันลองทางถัดไปให้เอง

ส่วนที่ทำให้แดชบอร์ดลื่นคือ WS engine ที่ capture หน้าจอ tmux เป็น delta frame ทุก 50ms แล้วยิงผ่าน `/ws` พร้อมตรวจสถานะให้ด้วยว่า agent กำลัง busy / ready / idle หรือ crashed ไปแล้ว

เรื่อง federation ข้ามเครื่องเขาเซ็น HMAC และพัฒนามาถึง v3 แล้วครับ — v1 เซ็นแค่ `METHOD:PATH:TIMESTAMP`, v2 ผูก body เข้าไปด้วย (อันนี้เป็น default ที่แนะนำ), v3 เพิ่ม `FROM` กับ per-peer pubkey ความคลาดเคลื่อนของนาฬิกายอมให้ ±300 วินาที ส่วนความเชื่อใจระหว่างเครื่องเป็นแบบ **TOFU** คือ pin กุญแจครั้งแรกที่เจอกัน แล้วจำไว้เลย

## หลุมที่ผมเจอมาแล้ว เอาไปเลี่ยงได้

อันนี้สำคัญกว่าฟีเจอร์ครับ เพราะมันกินเวลาชีวิตจริง

**หนึ่ง — คำว่า oracle** ใน maw คำนี้หมายถึง agent instance หนึ่งตัว คือ repo ที่ clone ลงมาแล้ว spawn session ขึ้นมา เวลาสร้างด้วย `maw bud <stem>` มันจะเติม `-oracle` ท้ายชื่อให้เอง ดังนั้น **ห้ามใส่ `-oracle` ลงไปในชื่อ** ไม่งั้นได้ `fusion-oracle-oracle` มานอนรอ

**สอง — `maw wake` ไม่ได้ปลุกชื่ออะไรก็ได้** ถ้าไม่มี oracle repo ที่ชื่อตรงกัน มันพัง ทางเลี่ยงคือยิงไปที่ tmux target ตรง ๆ เลย: `maw hey <session>:<window>.<pane>`

**สาม — ช่อง `node` ใน config เป็นของบังคับ** ถ้าไม่ใส่ federation จะพังแบบเงียบ ๆ ซึ่งแย่กว่าพังแบบมีเสียงเยอะ

**สี่ — ที่อยู่ไฟล์ config ไม่ใช่ `~/.maw/`** อันนั้นเดาผิดกันบ่อย ของจริง default คือ `~/.config/maw/maw.config.json` หรือถ้าเปิด XDG ก็ `~/.local/share/maw/config.json` เช็กได้ด้วย `maw doctor xdg`

**ห้า — `maw hey` แปะ `[node:target]` ไว้หน้าข้อความทุกครั้ง** เพื่อบอกว่าใครส่งมา ซึ่งถ้าปลายทางเป็น AI ก็อ่านรู้เรื่องดี แต่ถ้าปลายทางเป็น shell command ดิบ ๆ มันพังทันที

## ข้อควรระวังก่อนเอาไปใช้

ผมต้องพูดตรง ๆ นะครับ ของนี้ยังเป็น **alpha** ใช้ CalVer และ license เป็น BSL-1.1 สถานะที่ผมอ่านมาคือ v26.6.14-alpha.829 ซึ่ง CHANGELOG ขยับไป bump #2827 แล้ว — เลขนี้บอกอะไรได้ดีมาก คือ surface ของมันเปลี่ยนเร็วจนคำสั่งที่ผมเขียนไว้ข้างบนอาจไม่ตรงกับเวอร์ชันที่คุณโหลดมา ถ้าจะใช้จริง เช็ก `git log` ก่อนเชื่อทุกคำสั่งครับ

ส่วนตัว Rust gateway ผมข้ามไป เพราะมันปิดซอร์ส และ Bun gateway เป็น default อยู่แล้ว ส่วน BSL-1.1 ถ้าใช้เป็นเครื่องมือภายในก็ไม่มีปัญหา

สุดท้าย บทเรียนที่ผมชอบที่สุดจากของชิ้นนี้ไม่ใช่เรื่องเทคนิค แต่เป็นเรื่องการตัดสินใจ — ตอนประเมิน เราเกือบจะทิ้งสคริปต์ `grid-tmux.sh` ที่เขียนมือไว้ เพราะคิดว่า maw แทนได้หมด แต่พอลอง spike จริงกลับพบว่า capture ของ maw เป็นแบบ unbounded ขณะที่สคริปต์เดิมใช้ sentinel แบบ bounded ซึ่งมันเสริมกัน ไม่ได้ทับกัน

เครื่องมือใหม่ไม่ได้แทนของเก่าเสมอไปครับ บางทีมันแค่มาเติมช่องที่เราไม่รู้ว่าว่างอยู่
