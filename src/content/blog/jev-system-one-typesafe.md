คืองี้ครับ ถ้าใครเคยเขียนโค้ดที่สั่ง LLM ว่า "ตอบกลับมาเป็น JSON แบบนี้นะ" แล้วมันตอบ ```json มาครอบให้ หรือใส่คำอธิบายเกินมาหนึ่งประโยค จน `JSON.parse` พัง — คุณจะเข้าใจปัญหาที่ Jev พยายามแก้ทันที

Jev เป็นโมเดลตัวเรือธงของ TypeSafe AI และเขาเรียกตัวเองว่าโมเดล **"System One"** ตามชื่อระบบคิดเร็วของ Kahneman ประเด็นสำคัญที่ต้องเข้าใจก่อนอื่นเลยคือ **มันไม่ใช่ LLM และมันไม่สร้างข้อความเลย** ไม่มีคำตอบเป็นประโยค ไม่มีการเล่าเหตุผล

สิ่งที่มันกินเข้าไปคือ `state` (ข้อความ หรือ JSON) บวกกับชุด "คำถามที่มีชนิดข้อมูลกำกับ" แล้วมันคืนคำตอบที่เป็นชนิดนั้นออกมา พร้อม probability ที่ calibrate แล้ว

ผมชอบเปรียบเทียบแบบนี้ครับ LLM เหมือนนักเล่าเรื่องที่คุณจ้างมาเป็นเสมียนกรอกฟอร์ม — เขาทำได้ แต่เขาอยากเล่าไปด้วย ส่วน Jev คือ**เครื่องคัดเหรียญ** หยอดเข้าไปแล้วมันบอกได้แค่ว่าเหรียญนี้ลงช่องไหน และมั่นใจแค่ไหน พูดไม่ได้ แต่คัดแม่นและเร็ว

## มีแค่ 3 ปุ่มให้กด

Jev ไม่มี schema ซับซ้อนให้ออกแบบ มันมี primitive แค่ 3 ตัว

- `choice` — เลือกหนึ่งอันจากตัวเลือกที่ไม่มีลำดับ ได้ถึง 255 ตัวเลือก คืนค่าที่เลือกมาพร้อม probability และ confidence
- `score` — ใช้กับสิ่งที่มีลำดับ ตั้งได้ 2 ถึง 10 ระดับ คืนเป็นเลขทศนิยม คือมันตกอยู่ระหว่างระดับได้
- `noul` — ใช่/ไม่ใช่ คืนค่า P(yes) ระหว่าง 0 ถึง 1 ตัวนี้ไม่มีฟิลด์ confidence นะครับ

และจุดที่น่าสนใจคือ ทุกคำถามในหนึ่ง request **มองเห็น state เดียวกัน แต่ถูกประเมินแยกกันขนานไป** คำตอบของข้อหนึ่งไม่เคยเป็น context ของข้ออื่น ซึ่งมันแปลว่าคุณเอาคำตอบข้อแรกไปเป็นเงื่อนไขของข้อสองไม่ได้ ต้องยิงสอง request

## ที่มันคุ้มจริง ๆ คือการถามทีเดียวเยอะ ๆ

TypeSafe เรียกแพทเทิร์นนี้ว่า **speculative fan-out** เพราะคำถามข้อที่เพิ่มเข้ามาเกือบจะฟรี เขาเลยแนะว่าให้ถามรวบไปในคำขอเดียวเลย

ใน cookbook ของเขาระบุว่า การรวม 13 คำถามไว้ในคำขอเดียว ถูกลงประมาณ 12 เท่าและเร็วขึ้นประมาณ 10 เท่า โดยได้คำตอบเท่าเดิม — อันนี้ต้องวงเล็บไว้ว่าเป็นตัวเลขจากเอกสารเขาเอง ไม่ใช่สิ่งที่ผมวัดเองนะครับ

อีกสามแพทเทิร์นที่เหลือคือ confidence-gated routing (ทำอัตโนมัติเฉพาะเมื่อมั่นใจพอ ไม่พอก็ส่งต่อให้คน), composite scoring (ซอยเป็น score ย่อย ๆ แล้วถ่วงน้ำหนักรวมเองในโค้ด) และ intent routing (choice ไปยังปลายทาง พร้อมมีช่อง `other` ไว้ด้วย)

## เรื่อง confidence ที่อย่าเข้าใจผิด

Jev เทรนด้วย RLCD เพื่อให้ probability มัน calibrate — แต่ข้อความสำคัญคือ calibration นั้น **ใช้ได้กับกลุ่มของการทำนาย ไม่ใช่กับคำตอบเดี่ยว ๆ** ส่วน confidence เองก็มาจากว่าการแจกแจงความน่าจะเป็นมันแหลมแค่ไหน

วิธีใช้ที่เขาแนะคือมองมันเป็นแกนที่สอง: มั่นใจสูงก็ลงมือเลย กลาง ๆ ก็ให้ยืนยันหรือปักธงไว้ ต่ำก็โยนให้คนตัดสิน และ **threshold ควรขึ้นลงตามความเสี่ยงของการกระทำ** การคืนเงินกับการติดแท็กบทความไม่ควรใช้เลขเดียวกัน

เคล็ดที่ผมว่าดีมากคือ เอาคำถามทั้งหมดกับ threshold ทั้งหมดไปกองไว้ใน constants file เดียว เพราะนั่นแหละคือไฟล์ที่มนุษย์จะรีวิว

## ข้อจำกัดที่ควรรู้ก่อนลอง

มันรับแต่ข้อความ ไม่รับภาพ เสียง วิดีโอ และภาษาหลักคือ**อังกฤษ** ภาษาอื่นรับได้แต่แม่นน้อยกว่า — สำหรับงานไทยคือ "ต้องทดสอบก่อน" ไม่ใช่ "ใช้ได้เลย"

และมันไม่ใช่โมเดลสำหรับเอเจนต์เขียนโค้ด เอาไปแทนตัวที่อยู่หลัง Claude Code ไม่ได้ วิธีที่ถูกคือใช้เอเจนต์เขียนโค้ดที่ไป *เรียก* Jev

ปิดท้ายด้วยคำเตือนตามสไตล์ผม: ราคา ลิมิต และรหัสรุ่นของพวกนี้ขยับได้ตลอด ข้อมูลในโน้ตผมเป็นของช่วงปลายเดือนกันยายน 2026 ถ้าจะเอาไปคิดต้นทุนจริง ไปเช็กหน้าเอกสาร models ของเขาเองอีกรอบนะครับ
