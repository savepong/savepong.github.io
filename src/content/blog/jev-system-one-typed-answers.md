ถ้าคุณเคยเขียนโค้ดที่สั่ง LLM ว่า "ตอบเป็น JSON แบบนี้นะ" แล้วต้องมี try/catch ล้อมไว้ เพราะบางทีมันแถมคำว่า "Sure! Here's the JSON:" มาให้ด้วย — เรื่องนี้จะถูกใจครับ

TypeSafe AI ทำโมเดลชื่อ **Jev** ออกมา และจุดขายของมันคือสิ่งที่ฟังดูเหมือนข้อเสีย: **มันไม่ generate ข้อความเลย**

## มันทำงานยังไง

อินพุตมีสองก้อน หนึ่งคือ `state` ซึ่งเป็นข้อความ หรือ JSON object หรือ array ของข้อความ สองคือ `questions` ซึ่งเป็นคำถามแบบระบุชนิดข้อมูลไว้แล้ว

เอาต์พุตคือคำตอบตามชนิดนั้น พร้อมความน่าจะเป็น จบ ไม่มีประโยคเกริ่น ไม่มี markdown fence หลุดมา

ชื่อ "System One" มาจาก System 1 ของ Kahneman — การคิดแบบเร็ว ไม่ได้ครุ่นคิด ผมชอบเปรียบว่า LLM เหมือนคนที่คุณถามแล้วเขาเรียบเรียงคำตอบเป็นย่อหน้าให้ ส่วน Jev เหมือนเครื่องวัดในแล็บ คุณจี้ไปที่จุดหนึ่งแล้วมันขึ้นตัวเลข มันคุยกับคุณไม่ได้ แต่ค่าที่ได้เอาไปต่อในโค้ดได้ทันที

## มันมีแค่สามคำถาม

- `choice` — เลือกหนึ่งจากตัวเลือกที่ไม่มีลำดับ ได้ถึง 255 ตัวเลือก
- `score` — ระดับที่มีลำดับ 2 ถึง 10 ระดับ และคืนค่าเป็น float ได้ คือคะแนนตกคาบระหว่างระดับได้
- `noul` — ใช่/ไม่ใช่ คืนค่าความน่าจะเป็นที่จะเป็น "ใช่" ระหว่าง 0 ถึง 1

น้อยมากครับ แต่พอคุณเอาสามอันนี้ไปประกอบในโค้ดเอง มันครอบคลุมงาน classification, routing, scoring, guardrails ได้เกือบหมด

จุดที่ผมคิดว่าสำคัญและคนมักพลาด: **คำถามทุกข้อในหนึ่ง request มองเห็น state ก้อนเดียวกัน และถูกประเมินแยกกันขนานกัน** คำตอบข้อหนึ่งไม่ได้เป็นบริบทของข้ออื่น ถ้าคุณคิดว่าจะถามแบบลูกโซ่ "ข้อ 2 ให้ดูคำตอบข้อ 1" — ไม่ได้ครับ ต้องยิงสอง request

## ท่าที่ผมคิดว่าเป็นแก่นจริง ๆ

เอกสารเขาเรียกว่า **speculative fan-out** หลักคิดคือคำถามเพิ่มมันเกือบฟรี เพราะฉะนั้นยัดคำถามเยอะ ๆ ไปใน request เดียว

ตัวเลขจาก cookbook ของเขาคือ 13 คำถามรวมเป็นก้อนเดียว ถูกลงประมาณ 12 เท่า เร็วขึ้นประมาณ 10 เท่า และได้คำตอบเหมือนเดิม — อันนี้เป็นเลขที่เขาเคลมเองนะครับ ผมยังไม่ได้วัดด้วยตัวเอง

เหมือนสั่งอาหารครับ โทรไปสิบรอบสั่งทีละจาน กับโทรรอบเดียวสั่งสิบจาน ของที่ได้เหมือนกัน แต่เวลารวมกับค่าโทรต่างกันคนละเรื่อง ยิง request ใหม่ก็ต่อเมื่อ state หรือตัวเลือกรอบถัดไป**ขึ้นอยู่กับ**คำตอบรอบก่อนจริง ๆ

## ความมั่นใจ ใช้เป็นแกนที่สอง

Jev เทรนด้วย RLCD เพื่อให้ความน่าจะเป็นมันคาลิเบรต — แต่อ่านตัวหนังสือเล็กด้วยนะครับ การคาลิเบรตมันใช้ได้ **ในระดับกลุ่มของการทำนาย ไม่ใช่ต่อคำตอบเดี่ยว ๆ**

ค่า confidence มาจากความ "แหลม" ของการกระจายความน่าจะเป็น วิธีใช้คือแบ่งสามชั้น สูงก็ลงมือเลย กลางก็ขอยืนยันหรือปักธงไว้ ต่ำก็โยนให้คนหรือ fallback

และข้อนี้ผมเห็นด้วยที่สุด: **เกณฑ์ต้องสเกลตามความเสี่ยงของการกระทำ** การ auto-tag ผิดกับการ auto-refund ผิด มันไม่ใช่ความเสียหายระดับเดียวกัน จะใช้เลขเดียวกันได้ยังไง และถ้าคุณแค่อยากได้ตัวเลือกที่ดีที่สุด ใช้ argmax ไปเลย ไม่ต้องตั้ง threshold

คำแนะนำสุดท้ายในเอกสารที่ผมว่าดีมาก: เอาคำถามกับ threshold ทั้งหมดไปไว้ใน constants file เดียว เพราะนั่นแหละคือสิ่งที่มนุษย์จะมารีวิว

## อย่าเข้าใจผิด

มันไม่ใช่โมเดลสำหรับ coding agent ครับ ไม่ได้เอาไปสลับแทนตัวที่อยู่หลัง Claude Code หรือ Cursor ได้ ท่าที่ถูกคือใช้ coding agent เขียนโค้ดที่**เรียก** Jev

และมันรับข้อความเท่านั้น ไม่มีภาพ เสียง วิดีโอ ภาษาหลักคือภาษาอังกฤษ ภาษาอื่นรวมถึงไทยรับได้แต่ความแม่นต่ำกว่า — อันนี้ต้องทดสอบก่อนใช้งานจริง ผมยังไม่ได้ลองภาษาไทยเอง เลยยังพูดแทนไม่ได้

ข้อมูลทั้งหมดนี้เป็นสถานะ ณ 22 ก.ย. 2026 ครับ ราคา ลิมิต และ model ID พวกนี้ขยับได้ ก่อนอ้างอิงจริงไปเช็คหน้า models ในเอกสารเขาอีกรอบนะครับ
